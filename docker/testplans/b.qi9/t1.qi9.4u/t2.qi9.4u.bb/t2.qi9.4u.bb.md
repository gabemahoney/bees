**Context:** When an LLM passes a body containing the two-character sequence backslash-n (as JSON string escape), the MCP tool should store a real newline character, not the literal characters.

**Action (create):** Call the `create_ticket` MCP tool with a body containing the literal two-character sequence `\n` (backslash followed by n). Then retrieve the ticket with `show_ticket`.

**Expected:** The stored body contains a real newline character — not a literal backslash-n. The two lines are distinct when the body is displayed.

**Action (update):** Call `update_ticket` on the same ticket and set body to a string containing a literal `\t` (backslash followed by t).

**Expected:** The stored body contains a real tab character.

**Regression note:** Before this fix, `_sanitize_escape_sequences` did not exist and LLM-generated bodies with JSON escape sequences were stored verbatim as two-character literals.
