**Setup:** Configure bees with a parent wildcard scope (e.g. `/projects/**`) that has no hive named "tickets". The current working directory is a git repo under `/projects/` (e.g. `/projects/myrepo/`).

**Action:** Run `bees colonize-hive tickets /projects/myrepo/tickets` without providing an explicit `--scope` argument.

**Expected:** The new hive appears registered under the exact repo scope key (e.g. `/projects/myrepo/` or `/projects/myrepo`), not under the wildcard parent scope `/projects/**`. The wildcard scope's hive list is unchanged.

**Regression note:** Before this fix, `find_matching_scope` would return the wildcard parent scope as the best match, and the hive would be registered there. Now `_find_exact_scope` is used, which only returns a scope with `wildcard_tier == 0`, so a new exact-path scope is created instead.
